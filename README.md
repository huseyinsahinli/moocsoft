# Moocsoft website

Static HTML deployed from this repository to GitHub Pages. Existing legal-policy URLs and app import pages are consumed by published apps; preserve their contents and routes when editing marketing pages.

## Editorial content

- Edit articles in `content/*.mjs`, then run `node scripts/build-guides.mjs`.
- Commit both source modules and generated HTML/sitemap changes.
- Each new article should specify its actual `published` date (`YYYY-MM-DD`). Set `modified` only for a substantive article revision; older articles retain their original publication date.
- The build refreshes guide totals, QuitBit reading lists and marketing-page favicon links. It does not edit legal pages.
- Update non-guide sitemap dates only when those pages change meaningfully.
- Health content must distinguish record-keeping from treatment, link to primary sources where appropriate, and avoid promising medical outcomes. Store links must reflect verified platform availability.
- High-intent guides may set `appPreview: true` to show the matching conversion block from `content/app-previews.mjs`. Use real public app screenshots, accurate captions and current purchase boundaries; do not imply unsupported features.
- `content/guide-media.mjs` registers original diagrams displayed in selected articles. The build uses each diagram consistently for Article, Open Graph, Twitter and image-sitemap metadata. Only images actually shown in an article belong in its sitemap entry.
- Link to trustworthy primary references in the paragraph they support, with descriptive anchor text and original explanations rather than copied passages. Editorial references are not paid links; do not mark all of them `nofollow`. References and images help readers, but do not guarantee search rankings, clicks or app installs.
- Add three deliberately chosen same-topic next reads in `content/related-guides.mjs` whenever publishing a guide. The build rejects missing, stale, self-linked or duplicate recommendations; the full topic hub remains accessible. Publication order must not decide the recommended reading path.
- `content/topics.mjs` separates editorial topics from the six-app catalogue. Development guides use a real service CTA and `/guides/development/`, not a fabricated app or store link. Their next steps may use the explicit development resources in `content/related-guides.mjs`; use `guideHref` for guide/resource cards and keep app-topic recommendations unchanged in meaning.
- A guide with an app preview may set `previewCopy: { heading, description }` to connect its task to the app. Screenshot assets, store destinations and purchase notes remain shared. Do not imply automatic imports from free web tools into the app.
- Article section navigation is a compact native menu before the answer on mobile and a sidebar on desktop. The small navigation script only sets its default when crossing the layout breakpoint; links and native expansion work without JavaScript. Layout changes alone do not reset article publication or revision dates.

## Reader discovery and editorial formats

`content/discovery.mjs` keeps explicit homepage picks, three same-topic product/tool starting reads and three task-based reading journeys. These are editorial choices, not popularity or conversion claims. `editorialFormat` may be `story`, `decision` or `puzzle`; the default remains `guide`. Labels describe the actual content. Fictional people and situations must be disclosed as fictional, never presented as customer testimonials or personal experience.

The English library at `/guides/` renders all guide links in static HTML. Its optional `guide-discovery` assets add local text/topic/format filtering without URL parameters, storage, cookies or network requests. With JavaScript disabled, the full library and topic links remain available. Keep curated selections validated, retain full topic-hub links and test filtering, reset, no-match behavior and mobile/no-JavaScript access.

Use `showToolAction: false` when the matching topic's free tool cannot help the article's task; this does not remove app download links. For example, the website habit calendar is not an app backup. A preview with no real screenshot is labeled as app features/access, not a visual demonstration. Choose a genuinely different reader question and format when useful; do not rename an old checklist a story or multiply near-duplicate pages for traffic.

## German pilot

The German reading hub at `/de/guides/` contains three full, editorially adapted translations, not a duplicate of the full English catalogue. `content/de-index.mjs` registers these translations; `content/de-products.mjs` contains corresponding localized app destinations and honest language/purchase notes. `scripts/build-localized-guides.mjs` runs inside the normal guide build. Translations do not increase English article counts or change their publication dates.

Only genuine equivalent pages belong in `content/localization.mjs`. Each English/German pair has reciprocal `en`, `de` and English `x-default` links, self-canonicals and a visible language selector. The smaller German hub deliberately has no `hreflang` pairing with the full English catalogue. Never redirect readers automatically or canonicalize German text to English. German URLs are static HTML and included in the existing sitemap.

German example amounts are illustrative euros, not exchange-rate conversions. Reuse numeric fixtures to preserve arithmetic, but translate table labels and captions. Existing official screenshots remain unedited and carry German captions identifying their English interface. App-language support is separate from website language: Frugal's iOS 9.9.10 release notes mention German, while Habit Tracker's current iOS language field lists English. Do not infer Android support or German-speaking customer service.

Run `node scripts/test-localization.mjs` alongside the existing marketing, attribution and service-guide tests. Check German pages and both directions of the language selector on mobile/desktop and without JavaScript. Do not include private market analysis or Search Console exports in the repository.

## Free printable worksheets

The classic and reverse 52-week charts, 100-envelope checklist and missing-number question sheet are free static website outputs in `assets/worksheets/`, separate from paid app features. Printable HTML is intentionally `noindex, follow`; the corresponding guide is the search destination. Browser printing needs no account, library or network request. Checkboxes are temporary and are not saved or imported into an app.

Edit `scripts/build-search-assets.mjs` (puzzle values live in `content/puzzle-worksheet.mjs`), make the development-only `sharp` package available, and run `node scripts/build-search-assets.mjs` before `node scripts/build-guides.mjs`. It emits deterministic CSV/HTML/native SVG files, 1200×675 PNG diagrams and 480/800/1200px WebP variants. No image library is loaded on the deployed site. Commit sources and generated outputs together.

The seven original diagrams remain in `content/guide-media.mjs`. Twelve article-specific worked charts live in `content/guide-charts.mjs`; other English guides use a relevant shared topic photograph from `content/editorial-media.mjs`. The three German guides use translated photo descriptions and captions. Every article has a visible representative image; new charts follow the section they explain, and topic photos follow the first section so the useful answer comes first. Photographs are explicitly labeled AI-generated editorial illustrations, not app screenshots or customer records. Real product screenshots remain separate. Adding visual presentation alone does not reset editorial dates or imply search/click results.

All article `<picture>` elements use width-based WebP `srcset` and layout-matched `sizes`, crawlable PNG/JPEG fallbacks, explicit dimensions, descriptive alt text and visible captions. Article/Open Graph/Twitter/image-sitemap references agree with the image actually shown. New masters are 1200×675, with 480/800/1200px WebP exports. Rebuild the original SVG-based charts with `node scripts/build-guide-charts.mjs` and photo variants with `node scripts/build-editorial-photos.cjs` (development-only `sharp`; no library ships to readers), then run the normal guide build. The selected JPEG photo masters and final built-in generation prompt set are in `assets/editorial/README.md`. Keep below-the-fold images lazy-loaded; do not apply that rule blindly to above-the-fold or largest-content images.

A guide may set `mediaAfterSection` to a one-based section number when readers need its calculator or answer before the illustration. It requires an existing registered diagram and a valid section; the default order for other articles is unchanged. This layout-only choice does not reset editorial dates. The cigarette-cost guide uses a direct calculator anchor and keeps its separate quit-date calculator link in context rather than as a competing first action.

## Free browser challenges and savings plans

The tools directory contains eight free website tools, registered in `content/tools.mjs` independently of the six-app catalogue. The math challenge's 15 original questions in three fixed five-question rounds, hints and explanations live in `content/math-challenge.mjs`; `scripts/build-math-challenge.mjs` is included in the normal guide build. Questions, round links and native answer disclosures work without JavaScript. The optional checker keeps each round separate, saves no score and sends no answers to Moocsoft. Copying a round link is user-initiated and includes no inputs or score; clipboard failure leaves a selected, manually copyable public URL. Preserve the original `mathChallenge` questions and `#puzzle-*` anchors. These exercises are not screenshots or levels from Math Riddles. Keep current store destinations and optional purchase boundaries explicit.

`scripts/build-savings-goal-tool.mjs` and `scripts/build-app-brief-tool.mjs` run in the normal guide build. The savings goal calculator makes an exact-cent schedule from the remaining target and reader-chosen future deposit count; cadence is a label, not a computed calendar or bank transfer. The brief builder produces a local text file for a development conversation, not an estimate, sent inquiry or app download. Both tools retain static instructions/worked examples without JavaScript, hide stale results after edits, and do not send or save entered data. Downloads and clipboard writes require explicit reader actions. Preserve these boundaries when extending the tools.

The 52-week calculator supports standard and reverse 13/26/52-week plans. In reverse mode the starting input means the final, smallest deposit; the displayed first deposit, cumulative chart, print view and CSV all use the same selected order. `?order=reverse` selects the public mode without putting private amounts in a URL. Changing any input invalidates the old export. Calculator outputs are planning examples, not bank transfers or automatic imports into Frugal.
